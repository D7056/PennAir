**Stage 1:** Median blur. The first step separates the shapes from the background by denoising the image with a median filter. A small sliding window moves across every pixel in the image — for each pixel, you look at the window of pixels around it, compute the median value of that neighborhood, and replace the center pixel with that median. Critically, the output stays the same resolution as the input (an 800×800 image stays 800×800); you're not downsampling, you're running this operation once per pixel across the full image. The reason this helps separate shapes from background: the background is noisy and textured (grass), while each shape has a comparatively uniform, solid color. Median-blurring smooths out that background noise heavily, while barely affecting the already-uniform shape regions.

**Stage 2:** Absolute difference. Next, take the absolute difference between the original image and the blurred version. The result is mostly dark, because in any region that was already uniform, the median blur barely changed the pixel values, so subtracting the two leaves almost nothing. Look closely, though, and you can still see faint grain in the background where the blur did change things — the noisy grass texture leaves a visible speckled signal in this difference image, while the interior of a shape (say, the pentagon) stays essentially pure black, with no grain at all, because there was nothing for the blur to smooth away there.

**Stage 3:** Median of the absolute difference (MAD). Now take the median of that difference image, using the same sliding-window median operation as Stage 1, just applied to a different input. This step is the heart of the whole approach, and it's the direct analog of a standard deviation: it measures how much a given point typically stands out from its neighbors. In a flat, uniform patch — inside a shape — there was barely any deviation to begin with, so the median of that deviation stays close to zero, and the region stays dark. In the noisy grass, there's consistent, elevated deviation everywhere, so the median of it comes out meaningfully above zero, and that region turns visibly lighter. The key subtlety: Stage 2's difference image showed noise as sparse individual bright grains, but taking the median of that in Stage 3 aggregates those grains into a smoother, more reliable "this whole area is textured" signal — while the untouched dark shape interiors from Stage 2 stay dark. That contrast — dark shape, lighter background — is what actually makes the shapes separable from the background, regardless of what color or texture the background happens to be.

**Stage 4:** Extracting outlines and centroids. With that separation in hand, thresholding the MAD image into a black-and-white mask and tracing its boundaries with cv2.findContours is comparatively simple — that's the only library function doing the actual heavy lifting; nothing else was used beyond core OpenCV. One requirement matters here: a contour has to be a fully closed loop for its enclosed area and centroid to be computed correctly, and this method reliably produces closed, clean loops around each shape, which is what makes it robust. Finding the centroid of each shape is then a matter of using OpenCV's moment functions on each closed contour, rather than something you'd need to derive by hand.

The last piece is filtering out noise: tracing contours over the mask picks up not just the five real shapes but also scattered small contours from residual background noise. The fix is filtering by area — small contours get discarded, large ones get kept. The specific cutoff (around 1000 pixels) wasn't derived from any formal criterion; it was chosen empirically as a number comfortably larger than any noise blob's area but smaller than any real shape's area.

# Development Iterations

**Iteration 1 — Naive edge detection.** The first approach ran a convolution kernel over the image to detect borders directly, on the reasoning that a shape's outline would show up as a clean, connected edge in the pixel matrix: wherever pixel values changed sharply from one neighbor to the next, that discontinuity was assumed to mark a shape boundary. This worked cleanly against a flat, single-color background — uniform regions produced almost no edge response, and a gradient-filled shape produced one continuous edge along its boundary that a fixed threshold separated easily from the flat interior. Introducing a textured, non-uniform grass background broke this immediately. Grass produces sharp pixel-to-pixel transitions constantly, at every blade and shadow, so the edge magnitude in the background was often just as high as the edge magnitude along an actual shape boundary. Because the threshold is a single fixed number applied everywhere in the image, there was no way to distinguish "this is a real boundary" from "this is background texture" without first knowing something about the local context — which a fixed global rule, by definition, does not have.

**Iteration 2 — Robust local statistics.** The fix was to abandon any single global threshold and instead judge each pixel against its own neighborhood. Two robust statistics do this: the local median, computed over a small window centered on the pixel, gives a "typical value" for that neighborhood, and is robust because a handful of outlier pixels can't drag a median the way they'd drag a mean. The local Median Absolute Deviation, or MAD — the median of |pixel − local median| over that same window — gives a robust analog of a standard deviation: how much that neighborhood normally varies, again resistant to a few extreme values skewing the estimate. Combining the two into a single score, how far a pixel sits from its own local median scaled by its own local MAD, produces a per-pixel measure of how unusual a point is relative to what's typical right around it. Critically, that score is computed independently at every location in the image, so it adapts automatically to whatever the local background looks like: a quiet, uniform patch gets a small MAD and is held to a tight standard, while a busy, textured patch gets a large MAD and is held to a looser one. Neither the shape's color nor the background's texture needs to be known in advance for this to work.

**Iteration 3 — Hand-rolled sliding window (abandoned for performance).** The first implementation computed a geometric median per window using `scipy.optimize.minimize`, with the window slid manually across the image one pixel at a time via nested loops. Getting this correct took a while: bugs included window bounds that were off by one, a window that wasn't actually centered on the pixel being processed, and edge pixels near the image border where a full window doesn't exist and needs to be clamped or padded rather than read out of bounds. Once correct, it was still far too slow to be usable — calling a numerical optimizer once per pixel means, for an 800×800 image, 640,000 separate optimization problems, and that cost only grows once the windows are made to overlap, as they need to for a smooth per-pixel result, rather than tiling the image into non-overlapping blocks.

**Iteration 4 — Switch to library-based filtering.** Rather than keep hand-tuning a slow custom implementation, the median computation was rebuilt on `cv2.medianBlur`, which computes exactly the same per-window median but as a compiled, heavily optimized OpenCV routine rather than a Python loop calling an optimizer. This produced identical output for a fraction of the runtime, and marked a shift in approach: instead of deriving every operation from first principles, the generic, well-understood pieces — median filtering, in this case — were delegated to a fast, well-tested library primitive, freeing the actual algorithm design, how those primitives get combined, to be the custom part.

**Iteration 5 — Ratio score with hysteresis thresholding.** With the local median and MAD in hand, a ratio score `R = |pixel − median| / (MAD + ε)` was computed at every pixel to flag likely shape boundaries, a large R meaning a pixel departs sharply from what's typical nearby. Thresholding R directly produced a noisy, scattered result rather than clean outlines, for a structural reason: by definition, in any neighborhood with real variation, roughly half of the pixels sit above their own local median, so a plain threshold on R lights up scattered pixels throughout the noisy background, not just along the shape edges. The fix borrowed hysteresis thresholding from classical Canny edge detection (`skimage.filters.apply_hysteresis_threshold`): pixels with a very high R are kept automatically as "strong," pixels with a middling R are kept only if they're connected to a strong pixel, and everything else is discarded. Because a real shape boundary is a strongly-responding line that's also spatially connected end to end, while background noise is strong only in scattered, disconnected specks, this reliably kept the former and dropped the latter — producing full, connected outlines around all five shapes in the static test image.

**Iteration 6 — The broken-ring problem.** Extracting contours from that thresholded outline exposed a structural weakness in the whole approach: the outline produced by hysteresis thresholding is only ever one pixel wide, and any small gap in it — even a single missing pixel — splits what should be one closed loop into two or more disconnected arcs. This matters because `cv2.contourArea` assumes a closed loop when it computes enclosed area; a broken arc fragment, evaluated on its own, computes an area near zero and gets discarded by the area-based noise filter downstream, even though the shape it came from is genuinely present and was genuinely detected. Morphological closing (dilate-then-erode) helped bridge small gaps, but the shape with the weakest edge contrast against the grass — the circle — never closed reliably: a kernel size that closed the circle's gaps in one test frame was large enough to merge or distort other shapes in another, and no single kernel size worked across all cases.

**Iteration 7 — Simplification: threshold the interior, not the edge.** The actual breakthrough was noticing that the MAD map, on its own, without ever computing the ratio score at all, already showed each shape as one solid, low-value region standing out against a noisier, higher-value background. This falls directly out of what MAD measures: a flat, solid-colored shape has almost no local pixel variation anywhere in its interior, so its MAD stays near zero across the whole shape, while grass never stops varying, so its MAD stays elevated everywhere. Thresholding the MAD image directly, rather than the ratio-and-hysteresis pipeline built on top of it, produces solid filled blobs instead of thin one-pixel outlines — and a filled blob doesn't have the broken-ring failure mode at all, since one missing or misclassified pixel in the interior doesn't disconnect anything the way one missing pixel in a one-pixel-wide ring does. This single change replaced roughly ten pipeline steps (ratio score, hysteresis thresholding, morphological closing, contour smoothing) with about five, and turned out to be both simpler and more robust than everything that preceded it.

**Iteration 8 — Performance for video.** Running the pipeline per frame on video revealed two distinct bottlenecks, unrelated to the algorithm itself. The first was leftover debug `print()` statements dumping full arrays to the console dozens of times a second, one for every frame, which is expensive purely as console I/O regardless of what's being printed. The second was that the MAD computation was still calling `scipy.ndimage.median_filter`, a general-purpose implementation, rather than `cv2.medianBlur`, the same compiled OpenCV routine already used everywhere else in the pipeline since Iteration 4. Removing the prints and switching that one remaining call over to `cv2.medianBlur` resolved the slowdown entirely, without changing a single line of the actual detection logic.

**Iteration 9 — 3D localization.** Recovering a 3D position for each shape required first identifying, automatically, which of the detected contours was the circle, since the circle was the only shape whose real-world size (a 10-inch radius) was known ahead of time. This used a circularity metric, `4π·Area / Perimeter²`, which evaluates to exactly 1 for a perfect circle and drops below 1 for any shape with corners, since a fixed area enclosed by a shorter perimeter is only achieved by a circle. Once the circle was identified, depth (Z) followed from the similar-triangles relationship between its known real-world radius and its measured radius in pixels, scaled by the camera's focal length: a circle that appears small in the image is far away, one that appears large is close, and the ratio between real size and apparent size gives distance directly. That single depth value was then reused for every other detected shape in the same frame, on the assumption that all five shapes lie on the same flat, camera-facing plane — meaning only one shape's true size needed to be known in advance to localize all five in 3D.

**Iteration 10 — ROS2 packaging.** The final stage wrapped the algorithm into a two-node ROS2 system: one node streams video frames out as image messages, and a second node subscribes to that stream, runs the detection pipeline on each incoming frame, and publishes the results — outline points and a 3D position per shape — as a `MarkerArray`. The two nodes are connected only by agreeing on a topic name, not by calling each other's code directly, so either one can be replaced or restarted independently without the other needing to know. This was developed inside a Docker container running the official ROS2 Jazzy image rather than a full Ubuntu VM, since a container produced a working ROS2 environment in minutes rather than requiring the overhead of installing and booting an entire separate operating system.
